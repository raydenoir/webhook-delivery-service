# Webhook Service

HTTP API для регистрации получателей webhook и приема событий.
Сервис хранит подписки, события и доставки в PostgreSQL, проверяет адреса получателей
и защищает API ключом доступа.

## Локальный запуск

Требуются Python 3.13, uv и Docker Compose. Команды выполняются из корня проекта.

```powershell
uv venv --python 3.13
uv sync --locked
Copy-Item .env.example .env
docker compose up -d --wait
uv run alembic upgrade head
uv run uvicorn app.main:app --reload
```

## Документация API

- [Swagger UI](http://127.0.0.1:8000/docs) - описание маршрутов и отправка запросов.
- [ReDoc](http://127.0.0.1:8000/redoc) - справочник API.
- [OpenAPI JSON](http://127.0.0.1:8000/openapi.json) - схема API.

Примеры тел запросов, ограничения полей, заголовки и коды ответов доступны
в документации API. Кнопка Authorize в Swagger UI принимает значение `API_KEY`.

## Настройки

Настройки задаются в `.env` или в окружении процесса. Переменные окружения
имеют приоритет. Значения в `.env.example` предназначены для локального запуска.

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Строка подключения к PostgreSQL |
| `API_KEY` | Ключ доступа к подпискам, событиям и доставкам |
| `ALLOWED_WEBHOOK_HOSTS` | JSON-массив разрешенных хостов получателей |

PostgreSQL 17 запускается через Compose и хранит данные в Docker volume.
Команда `docker compose stop` останавливает БД с сохранением данных.

## Прием событий

HTTP 202 подтверждает сохранение события и доставок для активных подходящих
подписок в одной транзакции. Повтор запроса с тем же ключом
идемпотентности и содержимым возвращает прежнее событие. Тот же ключ с другим
содержимым приводит к HTTP 409.

## Отправка webhook

Worker отправляет готовые доставки и проверяет очередь каждую секунду.

```powershell
uv run python -m app.worker
```

Флаг `--once` ограничивает запуск одним проходом до 100 доставок.
Команда для одной попытки конкретной доставки также доступна отдельно.

```powershell
uv run python -m app.sender <delivery_id>
```

Она берет доставку в статусе `queued` для активной подписки и отправляет POST
с событием и заголовком `X-Webhook-Id`. Статус и попытка доступны через API.
Повторный запуск для уже обработанной доставки возвращает `skipped`.
Временные ошибки приводят к повторным попыткам с паузами 10 и 30 секунд.
После трех попыток с временными ошибками доставка получает статус `failed`.
Ручной повтор неудачной доставки доступен через API и сохраняет историю попыток.

Срок захвата доставки составляет 60 секунд. Worker автоматически завершает
просроченную попытку с ошибкой `lease_expired` и назначает повтор в пределах
общего лимита трех попыток. Восстановление конкретной доставки доступно отдельно.

```powershell
uv run python -m app.recovery <delivery_id>
```

Результат такого запроса у получателя неизвестен. При повторной отправке возможен
дубль, поэтому получателю следует учитывать `X-Webhook-Id`.

При временной ошибке подключения к БД worker повторяет работу через 5 секунд.
В режиме `--once` такая ошибка завершает команду с кодом 1.
Логи содержат UUID доставки, статус и причину ошибки.

## Проверки

```powershell
uv run ruff check .
uv run ruff format --check .
docker compose --profile test up -d --wait postgres-test
uv run pytest
```

Тестовый PostgreSQL работает на порту 5433 и хранит данные во временной памяти.
Pytest применяет миграции и очищает таблицы перед каждым тестом и после него.
Обычная БД сервиса не используется, настройки из `.env` для тестов не требуются.

Для другого тестового сервера доступна переменная `TEST_DATABASE_URL`.
Имя базы должно быть `webhook_test`, ее данные удаляются при запуске тестов.
Одновременный запуск нескольких прогонов на одной тестовой БД не поддерживается.
